# Notes on the site

How the site is put together, for whoever builds the next page.

## Layout

| Path                           | What lives there                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `src/pages/`                   | Routes. `og/[key].png.ts` renders Open Graph images; `robots.txt.ts` writes robots.txt.                       |
| `src/layouts/BaseLayout.astro` | The frame of every page: head, skip link, header, `<main id="main">`, footer.                                 |
| `src/components/`              | `Seo.astro` (title, description, canonical, Open Graph, Twitter card), `Fonts.astro`, header and footer.      |
| `src/content/`                 | Content collections (docs, FAQ), defined in `src/content.config.ts`.                                          |
| `src/styles/`                  | `tokens.css` (colour, type, spacing tokens) and `global.css` (base styles, focus, skip link, reduced motion). |
| `src/lib/`                     | `site.ts` (shared facts and `href()`), OG image data and renderer, the sitemap integration.                   |
| `public/`                      | Files copied as they are (favicon).                                                                           |
| `scripts/`                     | `check-links.mjs` (internal link check over `dist/`) and `contrast.mjs` (contrast table).                     |
| `tests/`                       | `node --test`: unit tests, and checks over the built site when `dist/` exists.                                |

## Writing a page

```astro
---
import BaseLayout from "../layouts/BaseLayout.astro";
import { href } from "../lib/site";
---

<BaseLayout title="Getting started" description="One sentence for search results and link previews.">
  <section class="container page-section" aria-labelledby="page-title">
    <h1 id="page-title">Getting started</h1>
    <a href={href("/faq/")}>FAQ</a>
  </section>
</BaseLayout>
```

- Exactly one `<h1>` per page, inside the page's content. The layout provides the landmarks.
- Link inside the site with `href("/path/")`, never a bare `/path/`: the site lives under `/vyuha-site`, and the link check fails a link that misses the base.
- Colours only from the tokens in `src/styles/tokens.css`. To add a colour, add it to both themes, run `pnpm contrast` and commit `docs/contrast.md`.
- Anything that moves goes inside `@media (prefers-reduced-motion: no-preference)`.
- A page that needs its own link preview adds an entry to `src/lib/og-images.ts` and passes its key as `ogImage`.

## Docs and FAQ

Content lives in two collections, typed in `src/content.config.ts`:

- `src/content/docs/*.md`: long pages (`model.md`, `guide.md`). Front matter gives the title, description, eyebrow, lede and OG image key; the page in `src/pages/<name>/index.astro` renders it with `DocLayout`. `sectionize()` in `src/lib/sections.mjs` turns each `##` and what follows it into `<section id="…">`, so every part has an anchor and appears in "On this page".
- `src/content/faq/NN-slug.md`: one question each (`question`, `order`); the body is the answer, the anchor is the slug.

Link between pages with relative paths in Markdown (`../model/#budgets`). The link check also fails a `#fragment` with no matching id. Biome does not format these Markdown files: it would rewrite their YAML front matter.

The header and footer list the pages in `pages` in `src/lib/site.ts`; the current page's link carries `aria-current="page"`, and `DocPager` follows the same order.

## Product illustrations

The home page shows the product with HTML/CSS illustrations in `src/components/illustrations/`, not screenshots. Each sits in `Frame.astro`, a window with a mono breadcrumb, which is one `role="img"` with an `aria-label` that says what it shows. The data is invented: issue keys like `WEB-41`, roles instead of names ("engineer agent", "you"). Layout inside a frame follows the frame's own width (container queries), so the same illustration works in a column at 360px and beside text at 1440px. Colours only from the tokens; the accent marks what needs attention.

## Address, base and SEO

`SITE_URL` (default `https://vyuhalabs.github.io/vyuha-site`) sets Astro's `site` (its origin) and `base` (its path) in `astro.config.mjs`. The deploy workflow sets it. Canonical links, Open Graph URLs, `sitemap.xml` and `robots.txt` all follow it, so a custom domain later is a change to that one value.

`sitemap.xml` is written after the build from the HTML pages in `dist/` (404 excluded) by `src/lib/sitemap-integration.mjs`.
